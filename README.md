# Ordex — платформа для замовлень та звітів

Десктоп-програма на Python/Tkinter для ведення прайс-листа, бази клієнтів
та формування заявок на покупку у форматі Excel.

## Запуск

1. Встановіть Python 3.9+ (https://www.python.org/downloads/)
2. Встановіть потрібні бібліотеки:
       pip install openpyxl matplotlib requests
3. Запустіть програму:
       python3 main.py

При першому запуску програма сама створить файл бази даних order_app.db
у цій же папці.

**Важливо для .exe:** файл `order_app.db` і папка `orders/` завжди
створюються поруч із самим `Ordex.exe` (не десь у тимчасовій системній
папці), тому дані надійно зберігаються між запусками, навіть якщо ви
переносите весь `.exe` в іншу папку чи на інший диск — просто тримайте
його не на робочому столі напряму, а в окремій папці (Windows інколи
обмежує запис прямо на робочий стіл).

## Як користуватись

### 1. Завантаження прайс-листа
Меню "Файл" -> "Завантажити прайс-лист..." -> виберіть Excel-файл.
Програма сама намагається розпізнати колонки за заголовками:
код/артикул, назва/найменування, ціна, вага, од.вим.
Програма запитає дату, з якої діють нові ціни (можна залишити порожньо —
тоді ціни діють з сьогодні). Стару історію цін програма не стирає:
можна в будь-який момент довантажити оновлений прайс, і заявки надалі
формуватимуться за останніми діючими цінами.

Верхня панель програми має три пункти: **Файл** (завантаження прайс-листа),
**Налаштування** (відправники, сповіщення) і **Звіти** (усі звіти нижче).
У верхньому лівому куті — логотип і назва Ordex. У бічному меню зліва —
лише "Нова заявка" і "Історія заявок".

### 2. Відправники
Меню "Налаштування" -> "Відправники..." — тут один профіль об'єднує все,
що стосується одного відправника: спосіб оплати (як він відображається
у списку в заявці), телефон, ім'я, а якщо цей відправник відправляє
через API перевізника (наразі — Нова Пошта) — ще й сам API-ключ та дані
для автоматичного ТТН (місто відправника, Ref контрагента). Номер
відділення відправника тут не вказується — він обирається щоразу прямо
в заявці (може бути 1 або 7), бо один відправник може того дня
відправляти з різних відділень.

Щоб не вводити дані вручну, натисніть "Знайти дані за телефоном" —
програма спробує знайти відправника з таким номером серед
зареєстрованих на вашому акаунті Нової Пошти; якщо не вийде — підтягне
збіг із власної бази вже введених відправників.

Різні відправники можуть працювати з різними перевізниками — просто
створіть окремий профіль для кожного. При виборі способу оплати в
заявці телефон, ім'я відправника і перевізник підставляються
автоматично (перевізник можна змінити вручну, якщо потрібно).

### 3. Формування заявки (вкладка "Нова заявка")
Екран розділено на дві колонки: зліва — дані відправника (номер заявки,
відповідальний, спосіб оплати, телефон, ім'я відправника і, останнім
пунктом, відділення відправника — 1 або 7), справа — покупець та
одержувач, у послідовності: телефон одержувача, покупець, перевізник,
тип доставки, область, населений пункт, відділення (або
вулиця/будинок/квартира — для адресної доставки), тип одержувача
(фізична чи юридична особа — для юридичної з'являється поле ЄДРПОУ),
одержувач, оплата доставки (за замовчуванням — одержувач), кількість
місць, накладений платіж. Ці поля потрібні перевізнику для оформлення
ТТН.

Вікно програми має мінімальний розмір, але весь вміст вкладки "Нова
заявка" прокручується — колесом миші (прокручується саме та область,
над якою курсор: форма або таблиця товарів окремо) або смугою
прокрутки праворуч, тож кнопка "Сформувати заявку" завжди досяжна
незалежно від розміру вікна. Таблиця товарів має власну прокрутку —
можна додавати скільки завгодно позицій в одній заявці.

- Вкажіть номер заявки вручну, дата ставиться автоматично.
- В полі "Покупець" почніть вводити прізвище — якщо клієнт вже є в базі,
  програма підкаже і підтягне його дані (адресу, телефон, область, місто,
  перевізника). Якщо клієнта ще немає — просто впишіть ПІБ, він
  збережеться в базу після формування заявки.
- Поле "Телефон одержувача" також працює як пошук: почніть вводити цифри
  телефону (в будь-якому форматі — з пробілами, дужками, тире) — якщо
  цьому номеру вже колись формувалась заявка, програма підкаже клієнта і
  підтягне всі його дані (ім'я, адресу, область, місто, відділення) так
  само, як і пошук за іменем. Телефони відправника й одержувача самі
  приводяться до єдиного вигляду `+380XXXXXXXXX` одразу після виходу з
  поля — можна вводити як завгодно (`067...`, `380...`, з пробілами).
- Область і місто одержувача вводяться з підказками (почніть друкувати
  перші літери). Список міст поповнюється по мірі використання програми.
- У блоці "Додати товар" почніть вводити назву товару — програма підтягне
  код, ціну та вагу з прайс-листа. Якщо один товар має кілька модифікацій
  з різними кодами й цінами (наприклад, кілька варіантів "Виток" з різною
  ціною) — поле "Код" теж активне і працює як пошук: можна ввести код
  напряму, щоб точно вибрати потрібну модифікацію. Впишіть кількість і
  натисніть "+" — рядок додасться в таблицю, суму і вагу програма
  порахує сама.
- Кнопка "Сформувати заявку" створює Excel-файл у форматі зразка
  (папка orders/), зберігає заявку та дані клієнта в базу для подальшого
  використання.

### 4. Доставка: на відділення / адресна / самовивіз
При виборі перевізника (Нова Пошта, САТ, Делівері) можна вказати тип
доставки — "На відділення" (поле № відділення) або "Адресна доставка"
(поля вулиця, будинок, квартира). При виборі "Самовивіз" ці поля
неактивні, бо доставка не потрібна.

Поле "№ відділення" одержувача працює і як звичайне текстове поле, і як
пошук: якщо обрано перевізника "Нова Пошта" і для поточного відправника
(способу оплати) є робочий API-ключ — програма сама підтягує список
відділень указаного міста прямо з довідника Нової Пошти (список
завантажується у фоні, без гальмування інтерфейсу, і кешується по
місту). Якщо ключа чи з'єднання немає — підказки просто не з'являються,
номер можна ввести вручну як завжди.

### 5. Історія заявок і деталі кожної заявки
Вкладка "Історія заявок" показує всі раніше сформовані заявки з датою
створення, датою відвантаження, номером ТТН (якщо його створено) і
статусом доставки. Клік по заголовку будь-якої колонки сортує весь
список за нею (повторний клік — у зворотному напрямку). Подвійний клік
на рядку (або кнопка "Переглянути деталі") відкриває повну картку
заявки: дані відправника й одержувача, список товарів, суму, статус ТТН.

**Заявка без ТТН і "Дата відвантаження".** Якщо товар потрібно
відвантажити не одразу (наприклад, клієнт ще не оплатив) — просто
зніміть прапорець "Створити ТТН автоматично" перед формуванням заявки.
Вона збережеться в історії без номера ТТН і без дати відвантаження.
Коли товар справді готовий їхати — виберіть заявку в історії (або
відкрийте її деталі) і натисніть **"Створити ТТН"**: програма створить
накладну в цей момент, а сьогоднішня дата автоматично запишеться як
дата відвантаження. Так дата створення заявки і дата фактичного
відвантаження товару лишаються окремими й точними записами.

З картки заявки (і окремими кнопками в самій вкладці) можна:
- відкрити сам файл заявки (Excel) програмою за замовчуванням;
- створити ТТН (якщо заявка ще без нього) чи відкрити друкований бланк
  ТТН (PDF) — він зберігається одразу при створенні ТТН, а якщо з
  якоїсь причини не зберігся тоді, кнопка сама довантажить його з
  Нової Пошти при першому натисканні;
- скасувати ТТН (заявка лишається, скасовується лише накладна);
- видалити заявку повністю (для помилково створених — з автоматичним
  скасуванням її ТТН, якщо він був).

### 6. База клієнтів
Вкладка "Клієнти" в бічному меню показує всіх покупців, яких програма
запам'ятала (ім'я, телефон, область, місто, адреса, перевізник,
відділення). Кнопка "Експортувати в Excel" зберігає весь список у
файл — зручно для резервної копії чи роботи поза програмою.

### 7. Звіти та аналітика
У меню "Звіти" (верхня панель) — набір звітів за вибраний період
(дата з / дата по):
- **Зведення** — кількість заявок, загальна сума, вага, середній чек
- **Товари** — що купують найбільше, з графіком топ-10
- **Клієнти** — хто купує найбільше
- **Географія** — звідки/куди найбільше замовлень
- **Перевізники** — розподіл по перевізниках

Кожен звіт можна зберегти в Excel-файл або скопіювати в буфер обміну
одним натисканням — скопійовану таблицю можна одразу вставити в Excel
(Ctrl+V).

### 8. Автоматичне створення ТТН (накладних)
Меню "Налаштування" -> "Відправники..." — тут для потрібного відправника
(способу оплати) вкажіть перевізника і його API-ключ. **Для Нової
Пошти** додатково потрібні: місто та номер відділення відправника, а
також Ref контрагента-відправника і Ref контактної особи відправника —
це ваші ідентифікатори в системі Нової Пошти. Кнопка **"Отримати Ref
автоматично"** сама знаходить їх за API-ключем (запитує перший
зареєстрований на акаунті профіль відправника) — ручний пошук у
кабінеті знадобиться, лише якщо кнопка не спрацює.

На формі заявки — лише прапорець "Створити ТТН автоматично при
формуванні заявки" (увімкнений за замовчуванням); окремого поля номера
ТТН на формі немає, бо він стає відомим тільки після формування заявки.
При натисканні "Сформувати заявку" програма сама зв'яжеться з сервером
Нової Пошти, створить накладну і покаже номер ТТН у вікні підтвердження
та впише його в Excel-файл заявки. Вага посилки для ТТН береться з
загальної ваги товарів у заявці, оголошена вартість — із загальної суми
заявки. За замовчуванням доставку оплачує одержувач (можна змінити на
відправника прямо у заявці).

Якщо обраний у заявці перевізник не збігається з перевізником,
налаштованим для поточного відправника (способу оплати) — програма
попередить про це і сформує заявку без ТТН, замість помилки в
незрозумілому місці.

Якщо щось не вдалось (немає ключа, немає з'єднання, невірні дані) —
заявка все одно сформується як звичайно, просто без номера ТТН, а
програма покаже зрозумілу причину помилки. Створити накладну вручну
на сайті перевізника можна в будь-який момент пізніше.

### Скасування ТТН
Якщо ТТН створено помилково, або клієнт зрештою забрав товар самовивозом
— у вкладці "Історія заявок" виберіть потрібну заявку і натисніть
"Скасувати ТТН". Сама заявка і весь її запис лишаються в історії —
скасовується тільки накладна на перевізника. Це працює, поки посилку ще
не забрав перевізник фізично; якщо вона вже в дорозі, Нова Пошта поверне
помилку, яку програма покаже як є. Скасовані ТТН позначені сірим
кольором у списку заявок.

**Обмеження:** автоматичне ТТН зараз підтримує лише Нову Пошту і лише
доставку "На відділення". Для САТ і Делівері інтеграція поки не
підключена — програма чесно про це повідомляє замість того, щоб
імітувати роботу. Якщо у вас є технічна документація API цих
перевізників — інтеграцію можна додати так само, як для Нової Пошти.

Логіка звернень до API написана за офіційною специфікацією Нової Пошти
(v2.0, JSON), але жодного реального виклику до їхніх серверів під час
розробки не виконувалось (немає доступу до зовнішньої мережі й
реального ключа в середовищі розробки) — перший запуск варто зробити
на тестовій заявці з невеликою сумою.

### 9. Відстеження статусу доставки та сповіщення
Програма сама стежить за заявками з ТТН, які ще не позначені як
доставлені:
- при кожному запуску програми — одразу перевіряє їхній статус;
- далі — повторно, з інтервалом, який можна змінити в меню
  "Налаштування" -> "Сповіщення та відстеження..." (за замовчуванням
  30 хвилин). Перевірка працює, поки програма відкрита, навіть якщо
  вікно згорнуте — окремого фонового сервісу Windows для цього не
  потрібно.

Коли статус заявки змінюється, знизу справа екрана (біля годинника)
з'являється спливаюче повідомлення, наприклад:
*"Відправлення для Вовк Олександр Миколайович м. Тернопіль отримано."*
Повідомлення залишається на екрані, поки ви самі не натиснете
хрестик — воно не зникає автоматично. Показ таких повідомлень можна
вимкнути в тому ж діалозі налаштувань.

У вкладці "Історія заявок" з'явилась колонка "Статус доставки", а
рядки підсвічуються кольором: зелений — доставлено, жовтий — у дорозі,
червоний — не вдалось створити ТТН. Кнопка "Перевірити статуси зараз"
запускає перевірку вручну, не чекаючи наступного автоматичного циклу.

## Перевірка ключа Нової Пошти окремо від програми
Якщо автоматичне ТТН не запускається і незрозуміло чому, можна запустити
окремий діагностичний скрипт (без ризику створити зайву накладну):
    python3 np_diagnostic.py
Він запитає ваш API-ключ і крок за кроком перевірить: чи приймається
ключ, чи є на акаунті зареєстрований відправник (і сам знайде його Ref,
без ручного пошуку), чи знаходяться вказані місто й відділення. У кінці
покаже готові значення для вставки в Ordex -> Налаштування -> Відправники.

## Логотип: де він показується і як потрапляє на робочий стіл
Один файл `assets/ordex_icon.ico` відповідає за всі місця, де ви бачите
значок Ordex:
- **У самій програмі** — у верхньому лівому куті вікна (топбар) і в
  заголовку/панелі завдань Windows. Завантажується під час запуску з
  `assets/ordex_icon.ico` та `assets/ordex_icon_256.png`.
- **У зібраному .exe** — той самий `.ico`-файл вшивається прямо всередину
  `Ordex.exe` під час збірки (параметр `--icon` у GitHub Actions).
- **На робочому столі** — коли ви створюєте ярлик на `Ordex.exe`
  (перетягнути файл на робочий стіл або "Надіслати" -> "Робочий стіл"),
  Windows автоматично бере значок із самого `.exe`-файлу. Окремо
  розміщувати картинку на робочому столі не потрібно — вона вже "всередині"
  програми.

Якщо захочете замінити логотип — досить замінити файли в `assets/` (той
самий `.ico` з кількома розмірами всередині) і перезібрати `.exe`.

## Структура файлів
- main.py — головне вікно програми
- db.py — робота з базою даних (SQLite, файл order_app.db)
- price_import.py — читання прайс-листа з Excel
- order_export.py — генерація Excel-файлу заявки
- reports.py — звіти, експорт в Excel, копіювання в буфер
- carriers.py — інтеграція з API перевізників (ТТН, відстеження, бланки, відділення)
- np_diagnostic.py — окремий скрипт перевірки ключа Нової Пошти (не частина програми)
- autocomplete.py — поле вводу з підказками (у т.ч. живий пошук відділень)
- ukraine_regions.py — довідник областей та міст України
- assets/ — значок програми (ordex_icon.ico, ordex_icon_256.png)
- orders/ — сюди зберігаються згенеровані файли заявок і бланки ТТН (PDF)

## Що ще варто буде донастроїти
- Додати реальні варіанти "спосіб оплати -> телефон" (зараз є лише
  приклад "рр ІОМ").
- Перевірити автоматичне створення ТТН на реальному API-ключі Нової
  Пошти (не тестувалось наживо) — і повідомити про будь-які помилки,
  щоб їх виправити.
- За потреби — розширити список перевізників або довідник міст.
- Підключити API САТ і Делівері, коли з'явиться їхня документація.
